Method

A licence gives a team access to Claude. Practice on their own projects is what gets them using it.

Every engagement follows the same three moves. I train people on their real work, I listen to the questions they ask, and I build the tools those questions point to.

  1. 01

    Train on the team’s own work

    I build each session around documents and tasks the team already has, such as research, document analysis, reports, proposals and project administration. A typical exercise has Claude organise points gathered from several documents, and the consultant review the result before it goes into their normal workflow.

  2. 02

    Collect the questions people ask

    Training produces questions such as “Could it compare these two specs?” and “Where did I solve this before?”. Grouped together, they show which workflows are worth changing, for example document review or a knowledge assistant for past projects.

  3. 03

    Build in short loops with the people who will use it

    I study the existing process, redesign the workflow and build a prototype. The people who will use it test it, I improve it, and it goes into use. The next problem then starts the loop again.

Four ways to start

Each engagement is sized for one team. Pick the one that matches what you already know about where the work slows down.

  1. 01

    Workflow diagnostic

    Choose this when you know the work is slow but not yet where or why.

    I interview the people doing the work, map one or two workflows and estimate the value of changing them.

    You leave withA map of the current process, a ranked list of opportunities and a recommended plan.

  2. 02

    Prototype sprint

    Choose this when you already know which task you want to fix.

    I build one narrowly defined use case with agreed data and users, then test whether it works in practice.

    You leave withA working prototype, an evaluation against the agreed test and a decision to scale it or stop.

  3. 03

    Capability programme

    Choose this when you want a whole team using Claude well.

    I take a baseline through a team survey and leadership interviews, then run an enablement day and three practical labs built on the team’s real work. Office hours, workflow clinics and pulse surveys follow.

    You leave withA measured baseline, a trained team, and reusable examples, guidance and workflows.

  4. 04

    Embedded engineer

    Choose this when a larger team has a steady stream of workflows to improve.

    An architect or engineer from Bakshi Labs works inside your team two or three days a week. Each week runs through the same cycle of understanding, building, testing, improving and teaching.

    You leave withTools built inside the team’s own process, and people who know how to run them.

01Win work · Live project search

Strategic Project Discovery searches live procurement sources

The problem

Business development teams check the same procurement portals by hand, one sector at a time, and notices still slip through.

What I built

I built a single web page that runs a live search across 676 procurement sources in 36 categories. Each result is plotted on a world map with a fit assessment for sector, scale and geography, an estimated win probability and a one-line verdict.

It needs no server or database. The hosted version opens in demo mode with fictional opportunities, and a Gemini API key switches it to live searches.

Built with

  • React
  • Leaflet
  • Gemini with Google Search

02Win work · Bid-intelligence database

GrowthSignal collects public tenders and programmes into one database

The problem

Opportunities are spread across hundreds of procurement portals, development bank registers and news sources, so teams often find them late.

What I built

I built a self-hosted database that collects tenders, programmes, news and deal signals from more than 270 official sources in the UK, EU and US. Claude adds contacts, metrics, stage and location to each record and writes a daily briefing that leads with deals.

Records are ranked on sector fit, project stage, value and corroborating sources against the firm’s own target sectors, stages and countries. Search combines keywords with local embeddings across every table.

Built with

  • Next.js
  • SQLite with sqlite-vec
  • Claude

03Design · BIM model queries

ModelChat answers plain-English questions about a BIM model

The problem

Getting an answer out of a BIM model usually needs a specialist and a desktop licence.

What I built

I built a browser BIM viewer with a Claude chat panel. Claude answers by calling a fixed set of 14 tools: six query the model index for storeys, categories, spaces, properties and quantities, and eight act in the viewer to isolate, highlight, section and frame elements.

The test model is a ten-storey timber office from the NordicLCA project, exported from Revit as IFC4 with about 10,600 elements. It is preprocessed once into a cache and then loads instantly.

Built with

  • Three.js
  • web-ifc
  • Claude Code

Status

Recorded from a local instance, because the chat runs through a local Claude Code login.

04Design · Energy modelling

Reference Buildings Explorer shows energy model results in 3D

The problem

Energy model results sit in spreadsheets and HTML reports that are hard to compare across building types and climates.

What I built

I built an explorer for the US Department of Energy commercial reference buildings. It covers 16 building types in 16 climate zones, with their EnergyPlus geometry and simulation results in six interactive 3D views.

The whole explorer is one self-contained HTML file, generated by a Python data pipeline.

05Design · Material compliance

MaterialScan checks materials against three standards

The problem

Certification evidence for each product sits in spreadsheets, PDFs and email, so nobody can see the state of the whole palette.

What I built

I built a compliance dashboard for an anonymised lab and workplace project. It scores each product against Living Building Challenge 4.1, WELL v2 and the client brief, and shows the relevant standard text beside every verdict.

Each verdict links to the EPDs, HPDs and Declare labels behind it. The dashboard also lists the documentation still outstanding and every verdict correction with the rule behind it.

06Deliver · Document workbench

WorkNodesCanvas turns source documents into finished reports

The problem

Turning surveys, workshop notes and meter data into client documents takes hours of copying and rewriting.

What I built

I built a canvas with three kinds of node. Reference nodes preview PDFs, images, Markdown, Office files and web pages. Analysis nodes send an objective and the wired references to Claude. Presentation nodes turn the analyses into a PPTX deck, a DOCX document or an HTML page.

Every node keeps its previous runs, so a team can compare answers before a deck goes out.

Built with

  • Python helper
  • Vanilla JavaScript
  • Claude Code

07Portfolio · Housing retrofit

Southwark Retrofit Atlas ranks retrofit priorities for 149,062 homes

The problem

Portfolio owners need to know which homes to retrofit first, what it will cost and how far a fixed budget goes.

What I built

I built an atlas that joins the GLA building stock model, the national EPC register and ONS boundaries. It costs a retrofit package for each of Southwark’s 149,062 homes and ranks them on carbon, need and deliverability. Changing the budget or a weighting re-ranks every home in under a second.

The analysis finds 56,873 homes below EPC C, and 86% of them can reach it for a median cost of £5.8k. It also checks 7,045 commercial buildings against the minimum energy efficiency standard.

Built with

  • D3
  • Canvas map
  • GLA LBSM 2 and the MHCLG EPC register
